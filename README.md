# hxwl-10 编号牌领用归还台

考古探方编号牌的领用、归还与追溯台面。解决的问题：发掘队员给新遗迹挂牌时，
常从旧清单里挑到已发出的号码——本台在领用、建牌两道关口把这种情况当场指出来。

## 技术栈

React + Vite + TypeScript + CSS，数据存浏览器本机 localStorage，无需后端。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5110

## 测试

```bash
npm test
```

- `test:rules`：纯规则断言（重号、旧号重投、重复领用、归还、事件回放，共 15 项）
- `test:smoke`：jsdom 渲染整个页面，跑一遍建牌/领用/归还与"重开追溯"（20 项）

## 业务规则

- 牌按发掘季建，牌号全季不重复。
- 一块牌只跟一个遗迹单位；领用时写明探方、地层、领用人。
- 遗迹验收退场后归还，牌面状态（完好 / 磨损 / 污损 / 开裂 / 遗失补登）一并记下。
- 旧季号码重投前，必须确认没有未结束的关联：
  - 旧季同号还有未归还领用 → 拦下建牌，指出牌号、原探方、原领用人；
  - 旧季关联均已结束 → 勾选确认后才可重投。
- 重复领用（牌领出未还又被领用）→ 拒绝并指出牌号、原探方、原领用人。
- 任何时候都能跨发掘季看到全部未归还的牌。

## 资料 / 规则 / 本机记录 三层分开

| 层 | 位置 | 内容 |
| --- | --- | --- |
| 资料 | `src/data/reference.ts` | 发掘季、探方、地层、牌面状态等静态档案，以及首次打开的演示底账 |
| 规则 | `src/domain/` | 建牌 / 领用 / 归还校验、事件溯源状态机、派生查询，全是纯函数 |
| 本机记录 | `src/store/ledgerStore.ts` | 台账事件只追加、不改写，存 localStorage；重开页面整串回放 |

一次操作（建牌 / 领用 / 归还）落成一条事件。页面底部的「领用归还流水」直接读取
事件日志，每一次领用都追得到；「编号牌台账」里每块牌可展开完整领用归还历史。

「恢复演示底账」会清空本机操作、回到随包附带的示例数据。

## 目录

```
src/
  data/reference.ts        资料层：静态档案 + 演示底账
  domain/
    types.ts               事件模型与 replay 状态机
    rules.ts               建牌 / 领用 / 归还校验规则
    events.ts              事件工厂
    selectors.ts           台账列表、未归还、指标等派生查询
  store/ledgerStore.ts     本机记录层：localStorage 追加式事件日志
  components/              建牌台、领用台、归还台、台账表、流水、警示条
```
